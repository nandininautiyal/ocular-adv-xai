This file provides critical context, strict coding guidelines, and the current state of the repository for any AI agent assisting on this project. **Always read this file before suggesting architectural changes.**

## Project Goal
This research project evaluates how adversarial attacks on ocular biometric models (specifically **Xception + ArcFace**) affect their Explainable AI (XAI) heatmaps, and whether defences restore the original heatmaps, not only the label (Divergence analysis). Detecting attacks from heatmap consistency was the earlier "main novelty"; since the 2026-10-31 re-check it is **not** a contribution: it is already published for generic images (e.g. Ye et al., IJIS 2021), and heatmaps add nothing over prediction-only detection in our full 8-bit run (AUROC 0.927 vs 0.925). `src/detect/` and `11` stay for reference. The supervisor now asks for novelty in the model, the eye masks and the explanation method (see Deadline & Deliverables).

## Defaults (scripts on `main` once the six PRs are merged)
- **Budgets:** 1/255, 2/255, 4/255 (`--levels 1,2,4`, or the default `--epsilons 0.0039216,0.0078431,0.0156863`). Every attacked and noisy image is rounded to 8 bits; in `05` a budget that is not a whole number of levels (e.g. 0.0078) stops the run. `--no-quantise` / `--impl paper` only for the paper's float setting.
- **CW:** confidence margin `--cw-kappa 5` logits, success judged after 8-bit rounding. `--cw-kappa 0 --cw-float-success` reproduces the 27 Oct protocol, where rounding undid 37.5 % of the CW successes.
- **Defences:** JPEG quality 75 (`--jpeg-quality`) and 4-bit depth (`--bits`). Rows keep the names `jpeg` / `bit_depth`, so a parameter sweep is one run per setting with its own `--tag`.
- **XAI:** LayerCAM and Eigen-CAM at `block14_sepconv2_act` (8 × 8 maps), explaining the true class at every stage (and the adversarial class when the prediction flips).
- **Controls:** same-budget sign noise, the defence on the clean image, and the defence on the noisy image (`noise+defence`, the matched control for restoration).
- **Sampling:** smoke run `--seed 1 --max-images 8`, full run `--seed 2 --exclude-from images_<smoke tag>.csv`. With the same correct-image list this draws the same 600 images as the 25 and 27 Oct runs (checked); `14` with `--per-class 1` and the same seed and exclusion takes one of them per subject.

## Architecture & Codebase Structure
- **Vendored Code:** The `third_party/ABRobOcular/` directory contains reference implementations of the ArcFace model, data loaders, and attacks. **NEVER modify files inside `third_party/`**.
- **Model Signature:** The core model is an Xception base with an ArcFace head. It requires **dual inputs**: `[image, label]`.
- **Inference Rules:** During inference, attacks, or XAI generation, the `label` input MUST be a zero vector of shape `(N, n_classes)` to bypass the ArcFace margin penalty. Read `n_classes` from the model (`model.inputs[1].shape[-1]`) instead of hard-coding 300.
- **The vendored ArcFace layer returns softmax probabilities, not logits.** With scale s = 64 the top probability is exactly 1.0 for confident predictions, so its gradient vanishes. Anything that needs gradients (XAI, attacks) must use the margin-free cosine logits from `src/models/arcface_inference.py` (`get_margin_free(model)`). In eager code, never compute cross-entropy on `model.output`: Keras clips probabilities to [1e-7, 1 - 1e-7] and the clip has zero gradient (`model.fit` only works because graph mode reads the logits out of the Softmax op).
- **Image Contract:** All functions handling images must expect/return shape `(256, 256, 3)` (or a batch `(N, 256, 256, 3)`), dtype `float32`, bounded in `[0, 1]`.
- **Modules of the anatomy build:** `src/models/anatomy_model.py`: `build_anatomy_model(cfg, arch)` for `baseline`, `gap`, `attn`, `attn_mask`, `parts`, `attnet_gate`; `CUSTOM_OBJECTS` (used by `load_checkpoint`); `model_arch`, `part_names`, `attention_maps` (N, 8, 8, K), `part_receipt(..., units="cosine" | "logit")`; `bind_region` / `embed_regions` for the three-input gate model; `MaskTrainer`, a custom train/test step that adds the KL mask loss while the checkpoint stays the plain inference model; `cfg["model"]["backbone"] = "tiny"` builds every arch on CPU for tests. `src/data/masked_generator.py`: 03's augmentation applied to the image and its 64 × 64 label map, per-cell targets, masks64 I/O. `src/xai/shapley.py`: part-group masks, hiding baselines (blur, mean, inpaint), the 2^P coalition images, exact Shapley values and pairwise interactions, part masses of a map, rank agreement, deletion curves. `src/xai/part_baselines.py`: KernelSHAP (shap's enumeration and efficiency rule) and LIME (lime_image's kernel and ridge) in numpy, on part or patch players, aggregation of patches to parts, 256 × 256 attribution maps and their Jensen-Shannon divergence. `src/attacks/masking.py`: `with_attention_temperature(model, tau)` (same weights, attention logits divided by tau; `AttentionPool(temperature=1.0)` leaves old checkpoints and configs unchanged), `aas_pgd` (PGD whose step follows the temperature of a grid, default 1,2,4,8,16, after which the unscaled model's margin loss is largest; in the style of Adaptive Attention Scaling, IEEE 10658195; equal to `pgd` without attention), gradient and attention-saturation statistics.
- **Modules added by the six PRs:** `src/attacks/budget.py` (8-bit budgets: `levels`, `quantise`), `src/attacks/adaptive.py` (BPDA-PGD, EOT, transform-robust PGD), `src/eval/verification.py` (embeddings, EER, TAR at FAR, rank-1, subject-bootstrap CIs), `src/xai/seg_masks.py` (periorbital eye masks, mask-file I/O), `src/analysis/region_null.py` (area-baseline null). `src/compare/regions.py` gained label-map grids, areas, enrichment, entropy and occlusion-aware masses; `src/defences/inference.py` gained `make_defence` / `parse_defence`; `layercam` / `eigencam` take `return_raw=True`.

## Strict Coding Guidelines
1. **TensorFlow & Keras Legacy:**
   You MUST set the environment variable `TF_USE_LEGACY_KERAS = "1"` before importing TensorFlow to ensure compatibility with `tf_keras`.
   ```python
   import os
   os.environ.setdefault("TF_USE_LEGACY_KERAS", "1")
   import tensorflow as tf
   ```
2. **Attacks: standard implementations, vendored code only for replication.**
   `src/attacks/whitebox.py` has standard FGSM, BIM, PGD, MIM and CW-L2 on the margin-free logits; use these for the XAI study, with `epsilon` chosen explicitly. The default attack loss is the margin loss (best other logit minus true logit, which never saturates); `loss="ce"` keeps cross-entropy. CW accepts `epsilon=None` only for uniform calls and ignores it; the runner runs it once, with a confidence margin `kappa` and, with 8-bit rounding, `quantise_fn` so that success is judged on the rounded image. The vendored `_face` attacks have bugs (double softmax; BIM/MIM project onto the epsilon ball only after the last step; PGD ignores `epsilon`; "CW" is sign steps plus N(0, 0.1) noise), so they are exposed only as `paper_*` wrappers to reproduce the paper's ASR table. Load the vendored module from its file (as `whitebox.py` does): the package `__init__` imports PyTorch.
3. **Pure Functions:**
   All attack, defence, and XAI attribution methods must be implemented as pure functions without side effects (seeded randomness, inputs never modified in place).
4. **XAI Targets:**
   CAM heatmaps target the last 4-D activation before the head: `block14_sepconv2_act` for Xception (`find_feature_layer`). Do **not** use the raw `SeparableConv2D` output `block14_sepconv2`: it is pre-BatchNorm/ReLU and ~95 % of its activations are negative. Explain the margin-free logit, never the softmax output. For any other architecture pass the layer explicitly (`target_layer`, `05 --target-layer`); see Pitfalls.
5. **Tests:** every module ships with tests in `tests/` (pytest on CPU, using the tiny ArcFace model in `tests/conftest.py`). Run `python -m pytest tests -q` before opening a PR.
6. **8-bit budgets:** quantise with `src/attacks/budget.py` (`levels`, `quantise`); do not add another copy (`14` still carries a private copy of `quantise`, to be replaced by the import).
7. **Kaggle scripts:** every long-running script gets a smoke option (`--max-images` or similar), prints progress with a time estimate, and records the git commit and its settings in its summary JSON.

## Pipeline Overview
- `Phase 1 (XAI)`: Heatmap generation (`src/xai/attribution.py`) using LayerCAM and Eigen-CAM (sign-corrected). `size=None` returns the native 8 x 8 map; `return_raw=True` also returns each map's sum and maximum before min-max scaling.
- `Phase 2 (Attacks)`: Adversarial generation (`src/attacks/whitebox.py` & `blackbox.py`). Blackbox includes Monocle Blending (procedural stand-in for the unreleased monocle image, placed on the Haar eye box; where the cascade finds no eye, on the iris of the eye-mask label map or the Hough circle; else at the image centre) and Patch Occlusion (positions are (row, col), matching the paper's Fig. 7; changed in PR #14).
- `Phase 2b (Attack ablation)`: `src/attacks/ablation.py` + `scripts/13_attack_ablation.py` run FGSM/BIM/MIM from the vendored settings (double softmax, 5x step, projection only at the end, raw momentum; reproduced exactly, see `tests/test_ablation.py`) to the standard ones, fixing one flaw at a time, plus vendored vs standard PGD and CW. This is the evidence behind contribution C1.
- `Phase 2c (Adaptive attacks)`: `src/attacks/adaptive.py` + `scripts/14_adaptive_attacks.py`: non-adaptive PGD vs BPDA-PGD vs transform-robust PGD through JPEG and bit depth, on 8-bit images within whole levels of the budget. `success_after_defence_any_attack` is the per-image worst case over the attacks (the robust error Carlini et al. 2019 recommend reporting).
- `Phase 3 (Defences)`: Inference-time defences (`src/defences/inference.py`): JPEG compression and bit-depth reduction, with parameters via `make_defence("jpeg", quality=50)`. **Strip and Patch Augmentation are training-time defences** (`src/defences/training.py`): they need separately trained models, as does EAT.
- `Phase 4 (Compare)`: Heatmap divergence metrics (`src/compare/divergence.py`): Spearman and top-k intersection (primary), JS divergence, cosine, L2, global SSIM, centre-of-mass shift, computed on native-resolution maps. Region mass (`src/compare/regions.py`, runner flag `--concept-masks`): fraction of each heatmap on each region of the clean image, area-averaged to each method's map grid. Regions come from the heuristic masks (`src/xai/masks.py`: pupil, iris, sclera, periocular) or an eye-mask file (`--mask-source`); `dmass_` is the change from the clean map, `area_` / `enr_` the region's share of the image and mass / area, `massvis_` / `dmassvis_` the same over the pixels an occluder left unchanged.
- `Phase 4b (Detection)`: reference-free, training-free detection (`src/detect/`, `scripts/11_run_detection.py`): scores how much an input's heatmap changes under JPEG / bit depth (`xc_*`), against Feature Squeezing (`fs_l1_*`) and logit cosine (`pred_cos_*`). Kept for reference; **not a contribution** since the re-check. Thresholds and fusion use clean calibration images only, disjoint from evaluation images; fusion is robust z-scores (`RobustZFusion`, mean over scores; the earlier max-of-percentiles fusion saturated at 1.0). Maps explain the class predicted for the input, never the true class. Feature Squeezing here runs on a saturated softmax (clean scores of about 1e-23): compute it on logits before reusing it.
- `Phase 5 (Orchestration)`: The end-to-end runner (`scripts/05_run_experiment.py`) runs on Kaggle with the `.keras` checkpoint and the correct-image list from `04`. It explains the **true class** at every stage and includes three controls (random noise of the same budget; the defence on the clean image; the defence on the noisy image). Judge restoration against the defended clean map (`vs_defended_clean_*`), not only the clean map: JPEG moves heatmaps of clean images too. `--save-maps` writes every native map to `maps_<tag>.npz`.
- `Phase 6 (Analysis)`: `scripts/12_analyse.py` (laptop, no model) turns `rows_*.csv` (05) and `features_*.csv` (11) into the paper's tables, figures, `report.md` and `report_v2.md`. It first checks the row accounting against `summary_<tag>.json`. The v2 tables split results by target (true-class vs adversarial-class map) and outcome (attack succeeded or failed), test region shifts against noise and an area-baseline null (`region_null.csv`; `--areas` for runs without area columns), and compare restored with not-restored images within each condition. Statistics (`src/analysis/stats.py`): 95 % subject-cluster bootstrap CIs, Wilcoxon signed-rank tests on per-subject means (with the CI of that mean), subject-level permutation tests, Holm correction. Images of one subject are never treated as independent.
- `Phase 7 (Protocol and verification)`: `02_make_splits.py --protocol random | cross_session | open_set`; `03_train_baseline.py` gives all generators one sorted class list and writes `class_index_<tag>.json`; `15_eval_verification.py` reports EER, TAR at FAR 1e-2 / 1e-3 and rank-1 with subject-bootstrap CIs: P1 (all pairs of the pinned test set; inflated, reproduction only), P2 (templates vs probes on the training subjects; only for cross-session models), P3 (open-set, cross-session, unseen subjects).
- `Phase 8 (Data check)`: `16_check_dataset.py` (CPU): counts against the official VISOB numbers, whether frames numbered 1010 or higher are synthetic copies, test-train overlap, and per-image heuristic mask areas.
- `Phase 9 (Eye masks)`: `17_make_eye_masks.py` runs the periorbital segmentation model (zero-shot) and writes the mask file; `18_validate_masks.py` exports a labelling pack and scores masks against hand labels (`docs/mask_labelling.md`; local tools only).
- `Phase 10 (Anatomy-guided models)`: `03 --arch` with `configs/anatomy.yml` trains the heads of `src/models/anatomy_model.py` on the cross-session split. The mask models read 64 × 64 training masks from `21`. `04` and `15` evaluate any arch.
- `Phase 11 (Anatomical Shapley Attribution)`: `22` computes exact Shapley values of the recognition score over eye-part groups (2^5 = 32 coalition images per image, condition and hiding baseline) for clean, noisy, attacked (including BPDA through the defences and `aas_pgd`) and defended images, next to CAM and attention part masses, the parts receipt, KernelSHAP / LIME on the same parts (16 coalitions) and on patches, and verification pairs (genuine and impostor templates). `23` tests the shifts against the same-budget noise control (subject-level statistics, Holm), checks faithfulness with deletion curves, and reports the sampling error of the baselines against exact ASA, the verification shifts, run times and map agreement.
- `Phase 12 (Gradient-masking check)`: `24` on any two-input checkpoint: PGD success against steps and against the budget (must rise and reach ~100 % at 255 levels), pgd vs `aas_pgd` vs random-restart PGD, input-gradient and attention-saturation statistics; `masking_flags` lists every failed test. **No robustness claim (and no robustness difference between two models) without a run of `24` with no flag on every model involved.**
- `Phase 13 (Cross-dataset UBIPr)`: `20` prepares VISOB-like crops of UBIPr; `15 --modes x1` verifies zero-shot on them with our protocol (default, unchanged) or `--x1-protocol alonso2025` (their pairing: session 1 vs 2, both eyes one identity, left eyes flipped; `--x1-frontal closest|strict`). Our crops differ from theirs (7.6 Rs around the sclera centre), so quote the pair counts next to the paper's (8,600 / 438,600; ours 8,732 / 456,924 with `closest`) and never call it a reproduction of their numbers.

## Pitfalls
- `find_feature_layer` returns `block14_sepconv2_act` whenever that layer exists, even after an attention block is added on top of it: pass the layer to explain explicitly (`target_layer`, `05 --target-layer`) for any new architecture, or LayerCAM and Eigen-CAM silently explain the pre-attention features.
- Images are 240 × 160 crops stretched to 256 × 256 with nearest-neighbour (96 duplicated rows, 16 duplicated columns): irises are 1.5× taller ellipses, circle-based masks do not fit them, and masks must be computed in this model-input geometry (17 does).
- Consecutive frames of one (subject, condition, eye, phase) bucket are near-duplicates, so the random split is a reproduction of the base paper only: never use its accuracy to show that one model beats another.
- The `l2` column of `rows_*.csv` is the RMS distance between two heatmaps, not the size of the perturbation (use `pert_l2` and `pert_linf`).
- The local rehearsal images (and the tiny test model's inputs) are synthetic discs; the only real VISOB pixels kept outside Kaggle are the 4 images in `results/examples_full.npz`. Never use the synthetic ones for a data claim.
- The heuristic "periocular" region is the outside of one fixed ellipse (area 0.692459 on every image): report it as such, with enrichment or the area null, never as "skin". The learned masks are zero-shot until validated against hand labels (`18`).
- With `--mask-source FILE`, 05 also centres the monocle on the mask's iris, so its monocle images differ from those of a heuristic run.
- Bit-depth reduction alone misclassifies 4.7 % of clean images (JPEG 0.5 %): report restoration also on the images whose defended clean version is correct.
- `12_analyse.py` stops on any row-accounting mismatch, including against a `summary_<tag>.json` next to the rows file. It crashes in `restoration_by_outcome` when no attack in the rows succeeded (seen only on tiny-model test runs).
- A correct-image list from `04` that differs by even one image changes `df.sample`'s shuffle, so `05` draws a different sample and loses the pairing with earlier runs.
- `examples_<tag>.npz` keys begin with the image's position in `images_<tag>.csv`, not its `image_id`.
- Locally, `tests/test_ablation.py::test_vendored_settings_reproduce_the_vendored_code[bim/vendored]` fails with 2 TF threads (oneDNN on Windows; agreement 0.9984 < 0.999); it passes with default threading and on CI.
- **Anatomy models and ASA.** The parts receipt is exact for the score, not for pixels: an 8 × 8 cell of Xception sees most of the 256 × 256 image, so a "part" is what its attention map selects on the feature grid. `attnet_gate` needs masks at test time (`04` / `15 --region-masks`; `22` refuses it); the other heads need them only in training. `find_feature_layer` still returns the pre-attention features (see above). For `attn_mask` and `parts`, `val_loss` is CE + λ × mask loss; they still minimise it, but early stopping, the learning-rate drops, the best checkpoint and `best_epoch` follow `val_ce` (the validation CE, which is what `val_loss` is for every other arch), so every arm is selected by the same rule (`run_<tag>.json`: `monitor`, `best_monitor`). `03` stops if any train, validation or test image has no mask, unless `--allow-missing-masks`: `21` must cover all three splits, plus the open set for `attnet_gate`'s P3. A part absent from an image (no pixels; the eyebrow is often outside the crop, see `part_presence_<tag>.csv`) is an exact null player in ASA (phi = 0) and gets no mask loss, so compare a part only on images where it is present. The same area rule holds for `attn_mask`: an image whose eye region covers less than `min_part_area` gets mask-loss weight 0 (`run_<tag>.json` `mask_area_below_min` counts them per split). With 17's masks every pixel is in a part (the background is skin), so the inpaint game's empty coalition is the mean-colour image in every image: inpaint and mean share `v_empty`, and part of their agreement is built in (`23` reports `same_empty_share`). BPDA-PGD succeeds when it fools the model behind the defence it was computed through (`attack_success` of its rows, `attack_success_after_defence_rate`; `attack_success_undefended` keeps the undefended outcome); `fgsm` / `pgd` succeed on the undefended model. Rank agreement in `23` uses phi oriented like the ASA deletion order (`oriented_phi`). `attnet_gate` runs `15` P1/P2/P3 only: no masks exist for the external images of x1 (15 stops). ASA hides parts with the clean image's mask in every condition, and for defended conditions it explains the model on the defended image. The ASA deletion order is computed on its own game and favours itself: compare the other orders with random. Inpainting costs about 60 ms per coalition image and CPU thread. λ = 1 is untested at Xception scale: check the mask loss in the smoke run.
- Without the symlink privilege, Windows cannot run `02` (it builds a symlink tree); the CPU smoke of the anatomy chain replaced `os.symlink` with a file copy.
- Kaggle stops a session after 12 hours: smoke-run first and check that the estimate fits (the next-run notebook does both and stops leftover jobs before the limit).
